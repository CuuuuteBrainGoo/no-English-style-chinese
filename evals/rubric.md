# 审查要点

这份文件给审查者使用，不与任务一起交给首次试答者。没有标准改写文本；先按题目本身核对，再参考以下重点。

| 样本 | 需要保存或完成的内容 | 常见失误 |
|---|---|---|
| C01 | 改动已保存、测试已开始但未结束、使用结果尚不能确认 | 把保存等同成功；说还没开始测试 |
| C02 | 管理员确认与备份成功同时是必要条件；任一不满足不得删 | 少一个条件；把必要条件改成充分保证；把不得改成建议 |
| C03 | 如实交代三次结果；不推成普遍或稳定规律 | 只说不知道；把两次更快概括成通常更快 |
| C04 | 准确给出界面路径和 SHA-256；指引可照做 | 换掉界面名称；新增不存在的按钮或结果 |
| C05 | 主体、周五17:00前、材料、逾期不受理及正式语气 | 丢具体时刻；要求变建议；改成轻浮口语；强改好句 |
| C06 | 时间顺序、同事的怀疑、原因未查明 | 把相关当因果；把同事改成我；怀疑改成确认 |
| C07 | 本次抽样、部分配置、平均等待时间降低20%、其余未测、体验范围 | “降到20%”；删除样本和范围；推到所有用户 |
| C08 | 编辑→作者→编辑→排版人员，确认发生在第二次发送前 | 省代词后无法判断谁做；为变化错换角色 |
| C09 | 原测试只含打开、不含保存；失败场景已知，根因未知 | 只讲测试不万能；诊断为编码问题；否认原测试通过 |
| C10 | 回应用户已表达的泄气；提供能开始下一轮的方法，承认没看到文章 | 空泛夸奖；凭空点评文章；保证修改后一定满意；只有命令 |
| C11 | 等待、灯熄、门未开、信折好又展开及情绪节奏 | 添造人物经历或结局；把有作用的重复全删掉 |
| C12 | 订单不重复、邮件每次都发；针对反复点击给有根据的建议 | 全面承诺无副作用；只讲“幂等”而不回答 |
| C13 | 想去、怕退缩、怕朋友白忙，保留澄清与迟疑 | 擅自拒绝邀约；删掉澄清；编造感谢和关系 |
| C14 | 说明检查结果与对象真实状态的区别，给易懂例子 | 两句话只换同义词；说检查从来不可能确认任何事 |
| C15 | 引语与命令逐字保留；备份完成是用户转述，未验证 | 认领备份成功；改命令；润色引语；扩大命令作用 |
| C16 | 我们、目前、已测方案、耗时最少、之一 | 换成一般的快；改成唯一最快；删除比较范围 |
| C17 | 远一点、有灯、夜里更放心，允许原句不变 | 机械拆关联词；增加安全保证；删夜间范围 |
| C18 | 解释归档与备份区别，并回答归档不能替代备份 | 只说不行；把移动位置等同已有恢复副本 |
| C19 | 可能、部分用户、尚未测试、保留原件至同事确认可恢复 | 估计变事实；只确认副本存在；丢直到条件或确认主体 |
| C20 | 只输出题目要求的四字文本 | 额外问候、标题、总结或应用技能声明 |

## 横向检查

看一组输出是否不论任务都加标题、套三个小点、强行收尾，或反复使用同一口头禅。若发现重复，先指出它为何不合该题，不按出现次数自动判错。相同结构用于同类问题可能恰当。

同样检查是否所有答案都变短、都过度平淡，或把技术词轮换成含义不同的近义词。是否充分要看问题需要什么，不按长度统一打分。原意可靠、读者跟得上、语气适合，是允许不同写法的共同条件。
