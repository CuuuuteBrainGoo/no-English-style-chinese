# 行为评测

评测关注技能是否帮助完成真实任务，不计算“AI 味”或文字相似度分数。所有样本都是为本项目编写的虚构情境，没有用户的私人工作记录。

## 怎样试

让一个没有参与本次改稿的评估者读取 `SKILL.md` 和 [prompts.json](prompts.json)，按各题作答。只给任务需要的材料，不把 [审查要点](rubric.md)、预期答案或已知缺陷一起发给它。若要观察辅助例子的作用，再单独安排允许读取 `references/context-examples.md` 的一轮，并在记录中注明。

保留实际原始输出，再交给另一名审查者逐题核对。最好分开会话，避免前一题和指导语影响下一题。资源有限时可以批量作答，但应标明同批上下文会互相影响，不能假装是多次独立实验。

先查任务、原意和证据，再讨论表达。润色任务允许原样保留，不能把修改量当成绩；问答任务要回答问题，不能只输出修改说明。同一题可以有多种合适答案。

## 记录什么

至少记录技能版本或提交、输入范围、是否加载辅助文件、实际输出、审查结果与修改理由。区分三类结论：

- **阻塞问题：** 改变事实、条件、证据或责任；丢失关键解释；没有完成任务；出现隐私或发布范围错误。修正后复测相关题。
- **可改进：** 意思和任务没有问题，但生硬、含混、啰嗦、过度口语化，或多题持续出现同一种不必要段式。给具体依据，避免只说“不够像人”。
- **可接受：** 任务完成、语义可靠、表达适合场景。风格偏好不同不等于失败。

原始试答与工作审计保存在本地 `agents/local-evals`，默认不发布。需要公开结果时，只发布经审核的虚构输入、去除本机信息的输出和结论，并说明限制。不得复制工作日志或聊天记录来代替评测报告。

## 怎样迭代

先用反例说明问题，再判断应改核心指令、例子，还是评测本身。一个偶发措辞不值得升级成全局禁令。修正关键缺陷后复测受影响样本，并补少量不同措辞的新题，防止只是记住原答案。

想证明技能有帮助，还需要同模型、同任务条件下的有无技能对照、匿名评审和更多真实场景。当前 agent 试答只用于找缺陷；它们与写作者可能共享模型和上级指令，不能视为人类读者评估或独立统计证据。不得把“审查通过”写成跨模型有效率，也不得把结构校验当作语言质量证明。

## 对照与连续交流

比较“额外加载技能”和“未额外加载技能”时，两组用同一批原始任务，保留实际输出。将 A/B 位置打乱后交给未读条件标签的评阅者；映射表、来源文件与评阅输入分开。允许并列，也允许未加载的一组更好。共用模型、基础指令和少量样本会限制结论，不能把几题的偏好算成改善率。

独立作答与改写分开比较。若观察改写的作用，普通编辑与技能编辑应收到相同原文、任务，并获得相同的处理次数；不能只拿技能二次编辑后的文本与普通模型第一稿相比，就把差异全部归因于技能。主要结果保留全部任务，再单列实际修改的文本；未改样本中也可能有漏改。

把旧反例用于完善规则，另留未见材料验证。更换量表后重评同一批文本，属于量表开发与复核，不算新增的独立验证。记录实际加载了核心还是核心加案例，不能把一种加载范围的结果推广到另一种。

数字、字数上限、明确日期和条件须单独核对，不只依赖评阅者的印象。匿名重复文本可用于检查评分是否一致；同文出现分差时保留原始判断，并把评分波动与文字改变区分开。语言问题需指出具体表达及其语境影响，不因一个问题涉及多个分项，就把它算作多份独立证据；没有病句也不自动代表表达已贴切。

连续交流要逐轮给新消息，上一轮回答保存以后再交下一轮。若一次提供了全部问题，模型就能预知后续事实；这类结果须标为模拟对话，不能据此声称跨轮使用已经稳定。

可以观察事实更新、用户改变语气要求、同一件事向不同读者解释时的变化。新事实出现后应更新判断，已知限制仍须保留；术语的详略要服从当轮用途。单段短对话通过，也不代表长期交流不会形成固定腔调。
