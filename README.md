# no-English-style-chinese

让 AI 在中文交流中表达得更贴切：**删掉空话，也把值得说的话说充分。**

A skill for idiomatic Chinese in everyday AI conversations, reducing awkward English carryovers while preserving meaning, evidence, tone, and useful detail.

当前版本：**v0.1.0-rc.3**（候选版）。

## 为什么做这个技能

每天与 AI 大量交流时，它的表达习惯也可能影响我们的说话方式。有些回复没有明显病句，读起来却像英文句子的译文：词义勉强对得上，搭配、语序、强调的地方和说话的分寸都不太合适；有些则用抽象名词、套话和重复解释把简单的意思绕远了。

这个技能希望 AI 从事情本身和中文交流习惯出发组织回答，让中文用户读得自然、明白。它关注中文里不合适的英语词义、搭配、句法和语用迁移，不排斥已经自然融入中文的表达，也不据此断言模型实际先用哪种语言思考。

默认采用自然、克制的日常书面语。解释复杂问题时把理由说充分，谈技术时保留必要概念，涉及人的感受时保留情绪与分寸；不把所有回答压成短句，也不要求统一口吻。

## 适合用在哪里

主要用于与 AI 直接交流：日常问答、概念解释、技术沟通、方案讨论和进度说明。它指导 AI 怎样组织当前回答，不需要先准备一篇文章让它改写。

**本项目不是以设计一个语言改写技能为目的。** 核心原则也可辅助翻译或润色，但这些是补充场景。用于公文、稿件、通知等有专门规范的写作，可能不达预期；本技能不提供这些文体的完整写作规范。遇到这类任务，仍应遵守用户给定的格式、用语和篇幅要求，不能以“自然”为由改变约束。

它也不是 AI 文本检测器，不承诺消除可识别痕迹、保证事实正确，或改善长期语言习惯。

## 它怎样作判断

以下均为虚构情境，用来展示判断方法，不是固定替换表。

> **普通办事耽搁：** 我和妈妈在诊所，事情没办完，需要告诉家人会晚点回去。
>
> 可以说：“我和妈妈还在诊所，事情没办完，得晚点回去。”
>
> 此时“困在诊所”容易突出受困的意味，力度不贴合日常情境。若确实暴雨封路、无法离开，“困在诊所”又可能准确。选择随语境变化，不能把某个词永久禁用。

> **需要把理由说够：** 测试只检查了打开文件，没有检查保存功能。用户问，为什么测试通过后保存仍会失败？
>
> 可以说：“之前只测了能不能打开文件，没测保存。所以那次测试通过，并不能说明保存功能也正常。这次保存失败的原因还需要查。”
>
> 只说“测试通过不代表没问题”，没有解释这次检查的范围；直接补出失败原因，又会超出已知事实。

“完整性校验”“回滚”“幂等”是否保留，要看用户需要了解什么、操作什么。成套关联词、长句、正式措辞、礼貌和有作用的重复，也都可以恰当。更多判断见 [语境案例](references/context-examples.md)。

技能借鉴文学中选词的准确、叙述的次序和对人的体察，不模仿某位作家的口吻，不为文采编造细节。研究来源和适用边界见 [研究依据](references/research.md)。

## 怎么使用

无需 Python、Node.js 或其他运行依赖。

**先试用一次：** 在能够读取文件的 AI 工具中打开项目文件夹，让它读取 [SKILL.md](SKILL.md)，然后提出真实问题：

```text
请读取这个项目的 SKILL.md，按其中原则回答我的问题：
这次修改影响哪些功能？还有哪些地方没有验证？
```

工具不能读取文件时，可以把 `SKILL.md` 正文粘贴进对话，再接上问题。研究资料不必一并粘贴。这种用法只在工具实际收到这些指令的上下文中生效，不等于已经安装为长期技能。

**作为技能使用：** 按所用工具的技能安装说明，把本项目作为一个技能目录安装，保留文件的相对位置。技能内部名称是全小写的 `no-english-style-chinese`；仓库名称保留 `no-English-style-chinese`。

```text
no-english-style-chinese/
  SKILL.md
  references/
    context-examples.md
    research.md
  agents/
    openai.yaml
```

在已经识别该技能、支持 `$` 调用的工具中，可显式调用：

```text
$no-english-style-chinese
请解释这两种方案各自适合什么情况，以及你建议我选哪一种。
```

安装路径、重新加载和调用方式以当前工具的说明为准。下载文件、工具识别技能和某次回答实际应用了技能，是不同的事；请结合工具显示和实际回答核对。

## 文件与版本

| 文件 | 用途 |
| --- | --- |
| `SKILL.md` | 核心表达指令与技能说明 |
| `references/context-examples.md` | 按需读取的语境案例 |
| `references/research.md` | 研究来源与适用边界，普通问答不必加载 |
| `agents/openai.yaml` | 支持该格式的工具使用的界面元数据 |
| `README.md`、`LICENSE` | 使用说明与许可 |
| `.gitignore`、`.gitattributes` | 本地文件排除与文本格式约定 |

工作日志、交接文档、聊天记录、原始评测、开发用评测资料和本机信息不属于发行内容。`agents` 目录只公开 `openai.yaml`。

rc.3 收准了技能入口的用途说明，并精简发行内容；核心表达原则和语境案例沿用上一候选内容。本版未进行新的行为实验，不宣称语言效果提升。当前可供试用，仍需真实交流中的反馈；少量模型评审不足以证明跨模型或长期效果。

## 反馈

提供去除隐私后的问题与回复，说明哪里别扭、哪些意思必须保留。建议可以有多种，也可以判断原文无需改动。反馈应围绕具体语境，不能仅凭某个词判定表达好坏。
