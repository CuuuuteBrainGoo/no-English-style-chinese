# no-English-style-chinese

让 AI 用更好的中文表达：**删掉空话，也把值得说的话说充分。**

A skill for natural, precise Chinese responses. It guides choices in context, without phrase bans or a fixed voice.

这个项目面向每天用中文与 AI 交流的人。默认语气是自然、克制的日常书面语，既能把复杂事情讲清楚，也能容纳适当的情感、节奏和个人表达。

## 想改善什么

有些回复每句话都通顺，合起来却让人费劲：动作藏在抽象名词后面，术语一个接一个，先预告怎样解释，再重复已经说过的结论。另一种常见问题是改得过短，只剩“还不能确定”“测试通过不代表没问题”，把用户真正需要的解释也删掉了。

本项目把注意力放在表达的作用上：这句话在回答什么，读者还需要知道什么，哪些意思不能省，怎样说才贴切。

下面是虚构的交流情境，示范判断方法，不是固定替换模板。

> **已知情况：** 改动已保存；测试已经开始，但尚未结束。用户问能不能正常使用。
>
> **合适的回答之一：** 改动已经保存，测试还没跑完，暂时不能确认能否正常使用。
>
> “改好了，可以用了”把保存当成验证成功；“还没测试”又丢了已经开始这一事实。

> **已知情况：** 测试只检查过能否打开文件，没有检查保存功能。用户保存时失败，问为什么测试通过还会出错。
>
> **合适的回答之一：** 之前只测了能不能打开文件，没测保存。所以那次测试通过，并不能说明保存功能也正常。这次保存失败的原因还需要查。
>
> 多说这几句，是为了交代检查范围和当前仍未知的原因。

“虽然步骤多一点，但更稳妥”可以是很自然的中文。“完整性校验”“回滚”“幂等”也有各自的用途。技能不按单词或句式判定好坏，更不以它们判断一段话是不是 AI 写的。更多情况见 [语境案例](references/context-examples.md)。

## 怎么使用

核心指令在 [SKILL.md](SKILL.md)，支持资料在 `references` 中。无需 Python、Node.js 或额外依赖，也不会运行文字检测程序。

**先试用一次：** 在能够读取本地文件的 AI 工具中打开下载或解压后的项目文件夹，或把 `SKILL.md` 作为文件提供给 AI。再发送你的真实问题，例如：

```text
请读取这个项目的 SKILL.md，按其中原则回答我的问题：
……
```

如果工具不能读取文件，也可以把 `SKILL.md` 正文粘贴到当前对话，再接上问题；只需核心原则时，不必把研究资料一起粘贴。直接读取文件或粘贴指令只影响工具实际收到这些内容的上下文，不代表已经安装为长期生效的技能。

**作为技能使用：** 将这个仓库作为技能目录交给支持 `SKILL.md` 的工具安装，并保留 `references` 的相对位置。具体发现位置和启用方式以该工具的说明为准。在已识别技能的 Codex CLI 或 IDE 扩展中，可以显式调用：

```text
$no-english-style-chinese
请解释这次修改会影响什么，以及还有哪些地方没验证。
```

仓库名按项目约定保留 `no-English-style-chinese`；技能内部标识使用小写 `no-english-style-chinese`，供工具识别和调用。安装工具要求目录与技能标识相同时，安装目录使用小写即可。文件已下载、技能已发现、某次回答已应用，是三件不同的事；以当前工具实际显示和回复表现核对。

**只在一个 Codex 项目里使用：** 将发布包解压到你要使用它的项目的 `.agents/skills` 目录下，得到以下位置。没有这个目录时再创建；它用于让 Codex 查找当前项目的技能。

```text
你的项目/
  .agents/skills/no-english-style-chinese/
    SKILL.md
    references/
    agents/openai.yaml
```

保留包内相对目录，随后在这个项目的 Codex 会话里查找技能并显式调用；若没有显示，先检查路径，再按当前工具的说明重新加载。发布包在 `codex-cli 0.164.0-alpha.11.1` 的隔离项目中已通过技能发现检查：名称、启用状态和界面元数据均被正确读取。这个结果不等于所有宿主都兼容，也不保证每次问答自动触发。

独立技能目录适用于支持这一形式的 ChatGPT 桌面端、Codex CLI 或 IDE 扩展。Codex 可以通过内置的 `$skill-installer` 从其他仓库安装技能；在支持独立技能的 ChatGPT 桌面界面中，按 `@` 选择已识别的技能。网页和手机端的插件分发是另一种形式，本仓库尚未制作插件包。发现位置、界面和调用方式会随产品变化，安装时参照 [OpenAI 官方技能说明](https://learn.chatgpt.com/docs/build-skills)。本仓库提供技能文件，没有自动修改你的全局配置，也没有提交到插件市场。

## 设计选择

- **先保住意思。** 主体、完成状态、条件、范围、证据、语气和承诺都影响原意，不能为了顺口偷换。
- **正式与自然可以并存。** 技术说明、正式通知、朋友间的消息，各有合适的表达。
- **不给词语判死刑。** 不使用禁词表、句长上限、统一段式、机械替换或所谓“AI 味分数”。原文合适时允许不改。
- **向文学学习判断。** 借鉴选词、行文次序、轻重与分寸；不用作家标签拼成口吻，也不为增加文采编造事实。

项目名针对中文表达中不合适的英语句法和表达习惯，不意味着所有外来影响都有害。学术研究、作家访谈与本项目的编辑选择各有边界，见 [研究依据](references/research.md)。

## 怎样判断有没有改善

看实际回答是否完成了任务，意思是否准确，解释是否充分，以及措辞和语气是否合适。一个原句可以有多个好改法，也可能无需修改。

[评测说明](evals/README.md) 和 [任务样本](evals/prompts.json) 用于复核这些判断。格式校验通过只表示文件可读；少量 agent 试答也不能证明跨模型效果，更不能证明它会改善长期思维或表达习惯。当前是可试用、需要继续用真实交流检验的初版。

## 参与修改

提供一段去除隐私的回复，说明当时的问题、你觉得哪里别扭，以及哪些意思必须保留。若有改写建议，也请说明它解决了什么；不要求给唯一标准答案。

维护约定见 [AGENTS.md](AGENTS.md)。本地工作日志、原始审计记录、提醒脚本及截图默认排除 Git；`agents` 目录只公开技能元数据 `openai.yaml`。不要通过强制添加把这些本地材料提交上来。
