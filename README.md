# no-English-style-chinese

> **先欣赏一段 AI 味满格的自我介绍：**
>
> 好的，没问题！这是一个非常值得探讨的话题。接下来，我将以最直白、最不绕弯子的话，由浅入深、全面系统地为你介绍这个技能。在正式开始之前，我们需要明确一点：语言不仅是信息传递的重要载体，更是连接思想与情感的关键桥梁。在当今人工智能技术飞速发展的时代，掌握自然、高效且富有温度的中文表达，正变得愈发重要。本文将从项目背景、核心目标、主要功能和适用场景等多个维度，带你深入理解这一技能的独特价值。无论你是初次接触的新手，还是经验丰富的资深用户，相信都能从中获得有价值的参考。让我们一起解锁自然中文表达的无限可能！

**说人话：这个技能让 AI 少写上面这种话。**

再具体一点：让 AI 用中文回答时，**先按中文把事情想明白、说清楚，而不是把英文的词和句子逐一搬过来。**

它想做到的是：删掉空话，也把值得说的话说充分；表达自然了，事实、条件、证据、术语、情绪和文体仍然都在。

当前版本：**[v0.1.0](https://github.com/CuuuuteBrainGoo/no-English-style-chinese/releases/tag/v0.1.0)**（正式版）。

## 为什么做这个项目

很多 AI 中文回复并没有明显病句，意思也能猜出来，但读起来总有一点别扭：

- 每个词都译出来了，词义和轻重却不适合眼前的场景；
- 中文词语都在，句子的骨架、语序和重心仍像英文；
- 本来两句话能讲清的事，被抽象名词、背景铺垫和重复总结绕远了；
- 为了显得亲切或简洁，又可能补造细节、丢掉限制，或者把所有场合都说成同一种口语。

这个项目关注的不是中国人说英语时的“中式英语”，而是**中文表达里不合适的英语迁移**。它也不把问题笼统归结为“AI 味”：真正要检查的，是这句话在当前中文语境里是否准确、贴切、有用。

## 它到底能帮忙做什么

下面的生硬写法都是为说明问题而虚构的对照，不是固定替换表，也不是模型实际效果的成绩单。重点看每组展示的判断能力。

### 1. 不只翻译字面，还会选择合适的词义和力度

**场景：** 和妈妈在诊所办事，还没结束，需要告诉家人会晚回去。

> **生硬写法：** 我被困在诊所和我妈妈在一起，因为我们的事情尚未完成。
>
> **目标写法：** 我和我妈还在诊所，事情没办完，得晚点回去。

**展示的能力：** 不被英文词义和语序牵着走。普通办事耽搁说“还没结束”“走不开”更贴切；如果确实暴雨封路、无法离开，“困在诊所”又可能很准确。技能判断的是语境，不是把某个词永久禁用。

### 2. 可以重排句子，但不会把条件和证据关系改坏

**场景：** 测试只检查了导出，没有检查保存。用户问：“测试不是通过了吗，为什么保存还出错？”

> **生硬写法：** 测试被执行以验证导出功能，但保存功能没有被包含在此次验证的范围内，因此当前现象需要被进一步分析。
>
> **目标写法：** 之前只测了导出，没测保存。所以那次测试通过，并不代表保存也正常；这次保存为什么失败，还得另外查。

**展示的能力：** 拆掉拗口的被动句和抽象名词，把理由说够；同时保留“导出测过、保存没测、失败原因未知”三个事实，不为了说得干脆而编出根因。

### 3. 不用宏大开场和套话，也不把必要解释一起删掉

**场景：** 向不懂技术的家人解释“同步”和“备份”的区别。

> **生硬写法：** 在当今数字化时代，照片承载着无可替代的情感价值。同步与备份并非简单的功能差异，而是数据管理理念的两个互补维度。我们必须认识到，建立正确的数据安全意识具有重要意义。
>
> **目标写法：** 同步是让手机和电脑保持一致：手机删一张，电脑那边也会删。备份是另外留一份，手机里的原照片删了，备份还在。所以删手机照片前，先确认照片已经单独备份好，不能只靠同步。

**展示的能力：** 删除没有帮助的时代背景、价值宣告和伪辩证，但保留读者真正需要的区别、后果和操作提醒。目标是“充分但不绕”，不是越短越好。

### 4. 会让话更自然，但不会为了自然补造人情和故事

**场景：** 同事上周五临时替班，让自己赶上了家人生日聚会，想写几句感谢。

> **不合适的改写：** 你放弃原本重要的安排，替我解了燃眉之急，我真的特别感动。你的这份情谊，我会一直记在心里。
>
> **目标写法：** 上周五谢谢你临时替我值班，让我赶上了家里人的生日聚会。下次你有事需要人替班，尽管跟我说，我能安排就一定顶上。

**展示的能力：** 感谢可以具体、有人情味，但“原本有重要安排”“特别感动”“一直记在心里”都不是已知事实。技能不应靠拔高和编故事制造真诚。

### 5. 不把所有中文都改成聊天口气

**场景：** 检查正式通知：“申请人应于周五17:00前提交材料，逾期申请不予受理。”

> **不合适的改写：** 尽量周五前把材料交过来哦，晚了就不太好办啦。
>
> **目标处理：** 原句已经清楚，可以保留；若想方便阅读，也可以拆成两句，截止时间和逾期后果不变。

**展示的能力：** 正式、克制、书面并不等于生硬。“应”“不予受理”在通知里有实际作用，不能为了显得亲切而削弱期限和要求。允许不改，也允许正式中文。

## 一句话概括它怎样工作

1. **先看事情：** 用户真正要问、要做或要表达的是什么。
2. **再看意思：** 哪些事实、条件、证据、术语、情绪和关系必须保住。
3. **然后组织中文：** 按当前读者和交流场景选择词语、语序、重心与详略，不照搬英文骨架。
4. **最后回看：** 是否答完了问题，有没有补造或遗漏，是否像这个场合会使用的中文。

更多具体判断见 [语境案例](references/context-examples.md)。研究来源和适用边界见 [研究依据](references/research.md)。

## 适合与不适合

### 主要适合

- 中文日常问答、概念解释和方案讨论；
- 技术沟通、操作说明、项目进展和问题分析；
- 希望减少生硬英语迁移的翻译、润色等辅助场景。

它的主要用途是**指导 AI 怎样组织当前中文回答**，不要求用户先准备一篇文章让它改写。

### 不承诺什么

- 不是 AI 作者检测器，也不保证消除所谓“AI 指纹”；
- 不是禁词表、固定替换器或统一口吻生成器；
- 不保证事实自动正确，仍须核对来源、数字、条件和用户要求；
- 不提供公文、稿件、通知等专门文体的完整写作规范，这类任务可能不达预期；
- 不据此判断模型内部究竟先用哪种语言思考，也不承诺改善人的长期语言习惯。

## 怎么使用

无需 Python、Node.js 或其他运行依赖。

### 先试用一次

在能够读取文件的 AI 工具中打开项目文件夹，让它读取 [SKILL.md](SKILL.md)，再提出真实问题：

```text
请读取这个项目的 SKILL.md，按其中原则回答：
这次修改影响哪些功能？哪些地方已经验证，哪些还没有？
```

工具不能读取文件时，可以把 `SKILL.md` 正文粘贴进对话，再接上问题。研究资料不必一并粘贴。这种用法只在工具实际收到这些指令的上下文中生效，不等于已经安装为长期技能。

### 作为技能安装

**推荐下载正式版 ZIP：** [no-English-style-chinese-v0.1.0.zip](https://github.com/CuuuuteBrainGoo/no-English-style-chinese/releases/download/v0.1.0/no-English-style-chinese-v0.1.0.zip)。

1. 下载并解压，得到 `no-english-style-chinese` 文件夹。
2. 按所用工具的技能安装说明，将**整个文件夹**放到它识别的技能目录；不要只复制 `SKILL.md`，否则按需读取的语境案例会丢失。
3. 让工具重新加载技能，或按工具要求重开对话。安装后可以用 `$no-english-style-chinese` 显式调用；不支持 `$` 的工具，按它自己的调用方式使用。

也可以下载 GitHub 自动生成的 [源代码 ZIP](https://github.com/CuuuuteBrainGoo/no-English-style-chinese/archive/refs/tags/v0.1.0.zip)。两种方式内容一致；正式版附件已经把技能文件夹放在压缩包顶层，解压后少整理一层目录。

解压后的结构应为：

```text
no-english-style-chinese/
  SKILL.md
  references/
    context-examples.md
    research.md
  agents/
    openai.yaml
```

技能内部名称是全小写的 `no-english-style-chinese`；仓库名称保留 `no-English-style-chinese`。

在已经识别该技能、支持 `$` 调用的工具中，可以显式使用：

```text
$no-english-style-chinese
请解释这两种方案各自适合什么情况，以及你建议我选哪一种。
```

安装路径、重新加载和调用方式以当前工具的说明为准。下载文件、工具识别技能、某次回答实际应用技能，是三个不同环节，需要分别核对。

## 验证与版本边界

本项目通过独立生成、改写对照和匿名评阅检查实际表现，但现有实验规模较小，题目、生成者和评审也可能相近。结果只能说明特定批次中的现象，不能证明跨模型、长期或普遍有效。

v0.1.0 是首个正式发行版：收准技能入口的用途说明，重写项目介绍与安装说明，并精简发行内容。核心表达原则和语境案例沿用 rc.3；本次没有新增行为实验，不能把文档和打包更新理解成语言效果已经提升。当前可供使用，仍需要真实交流中的反馈。

## 反馈

欢迎提供去除隐私后的真实问题与回复，并指出：

- 哪一句别扭，像不像“用中文写英文”；
- 哪些事实、条件、术语、情绪或文体作用必须保留；
- 是想要更自然、更充分，还是只调整某一处。

反馈可以包含“这里不需要改”。具体语境比一个孤立的词更能说明问题。
